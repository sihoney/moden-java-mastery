# 🧵 스레드 vs 🧬 가상 스레드

## 🧵 전통적인 스레드 (플랫폼 스레드)

> **OS가 직접 관리하는 진짜 스레드**

특징:

* 생성 비용 큼
* 개수 제한 (수천 개면 한계)
* 스택 메모리 큼 (보통 1MB 이상)
* 블로킹 I/O 시 **스레드 자체가 멈춤**

그래서 서버에서:

> **"스레드 = 귀한 자원"**

---

## 🧬 가상 스레드 (Virtual Thread, Java 21)

> **JVM이 관리하는 초경량 스레드**

특징:

* 생성 비용 매우 작음
* 수십만 개 생성 가능
* 스택 메모리 작음 (수 KB)
* 블로킹 I/O 해도 **OS 스레드는 안 막힘**

즉:

> **"스레드 = 싸고 많은 자원"**

---

## 🧠 구조적 차이

### 플랫폼 스레드

```
Thread
 └─ OS Thread
      └─ 실제 CPU 실행
```

### 가상 스레드

```
Virtual Thread
 └─ JVM Scheduler
       └─ Carrier OS Thread
            └─ 실제 CPU 실행
```

가상 스레드는
JVM이 OS 스레드 위에서 **스케줄링**한다.

---

## 🧪 실무 차이 예시

### 전통 서버

* 스레드 풀: 200개
* 요청 1000개 → 800개 대기
* 응답 지연, 타임아웃 발생

### 가상 스레드 서버

* 요청 100,000개 처리 가능
* 각 요청당 스레드 하나 할당
* 블로킹 코드 그대로 사용 가능
* 복잡한 비동기 코드 불필요

---

## 🏁 한 문장 요약

> **가상 스레드는 “스레드 수 제한”이라는 문제를 제거한 혁명이다.**

이게 Java 서버 아키텍처를 완전히 바꿨다.
