# 🧠 `Files.lines(path)`의 진짜 의미

이 한 줄은 이렇게 보이지만:

```java
Files.lines(path)
```

실제로는 **“파일을 여는 행위”**이지
**“파일을 읽는 행위”**가 아니다.

---

## 🧩 JVM 안에서 실제로 일어나는 일

### 1️⃣ 호출 순간

```java
Stream<String> s = Files.lines(path);
```

이 시점에 JVM은:

* 파일 핸들을 연다
* OS에게 “이 파일을 읽을 거야”라고 등록한다
* **아직 파일 내용은 한 글자도 읽지 않는다**

즉, 이건:

> **읽기 예약**이지, 읽기 실행이 아니다.

---

### 2️⃣ 스트림은 **실행 계획**

`Files.lines`가 돌려주는 `Stream`은
데이터가 아니라 **데이터를 어떻게 읽을지에 대한 계획**이다.

그래서 이 단계에서는:

* 메모리 사용 거의 없음
* CPU 사용 거의 없음
* 파일 I/O 거의 없음

---

### 3️⃣ 실제 파일 읽기는 언제?

이 순간:

```java
s.forEach(...)
s.count()
s.collect(...)
```

이런 **terminal operation**이 호출되는 순간에만
JVM은 파일을 **한 줄씩 읽기 시작**한다.

---

## 🧪 왜 이것이 “지연 실행”인가

전통적인 코드:

```java
List<String> all = Files.readAllLines(path);
```

→ **지금 당장 파일 전체를 메모리에 로딩**

지금 구조:

```java
Stream<String> s = Files.lines(path);
```

→ **필요할 때, 한 줄씩, 흘려보냄**

그래서:

> **데이터가 흐른다**고 표현한다.

---

## 🧠 이게 왜 시스템적으로 중요한가

### 메모리

* 10GB 파일도 10KB 메모리로 처리 가능

### 안정성

* GC 폭주 없음
* OOM 방지

### 백프레셔

* 처리 속도가 읽기 속도를 자동으로 제어

---

## 🧬 비유로 이해하기

`readAllLines()` → 책을 통째로 복사해서 책상 위에 올림
`Files.lines()` → 책을 한 줄씩 읽어 내려감

---

## 🏁 한 문장 요약

> `Files.lines()`는
> **“파일을 메모리에 올리지 않고, 시간 속으로 흘려보내는 장치”**다.

이 개념을 이해하면
대용량 처리, 스트림, 리액티브, 비동기 I/O가
하나의 그림으로 합쳐진다.
