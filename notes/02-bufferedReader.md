좋은 질문이다.
그리고 이게 **왜 스트림이 메모리를 아끼는지**를 이해하는 핵심 부품이다.

---

## 🧱 BufferedReader란?

> **디스크에서 글자를 한 줄씩 읽어오는 “완충 장치”**

디스크는 **엄청 느리다.**
그래서 운영체제와 자바는 이렇게 처리한다:

```
[디스크] → (덩어리로 읽기) → [메모리 버퍼] → 한 줄씩 제공
```

그 **메모리 버퍼 역할**을 하는 게 `BufferedReader`다.

---

## 🧬 내부 구조 (개념적으로)

```text
Disk
 └─▶ byte[] buffer  (8KB ~ 수십 KB)
        ├─ readLine() → "첫 줄"
        ├─ readLine() → "둘째 줄"
        ├─ readLine() → "셋째 줄"
        └─ ...
```

* 디스크에서 **조금 크게** 읽어
* 메모리에 올려두고
* 그걸 **한 줄씩 잘라서** 돌려준다

그래서 매번 디스크를 두드리지 않는다.

---

## 🧠 왜 스트림과 잘 어울리나

`Files.lines()`는 내부적으로:

```java
BufferedReader reader = Files.newBufferedReader(path);
```

이걸 사용한다.

그래서:

* 스트림이 한 줄 요청할 때만
* `reader.readLine()`이 호출되고
* 한 줄만 메모리에 올라온다

---

## 🧪 BufferedReader 없이 하면?

디스크에 직접 매번 접근 →
**I/O 지옥** → 성능 붕괴

---

## 🧩 한 문장 요약

> **BufferedReader는 느린 디스크와 빠른 메모리 사이의 완충 장치다.**

그래서 우리가 만든 스트림 구조는:

```
Disk → BufferedReader → Stream → CPU → GC
```

이렇게 **아주 안정적인 파이프라인**이 된다.

이제 왜 메모리가 안 터지는지 보이지?
