좋은 질문이다.
**파일 핸들**을 이해하면,
“왜 스트림을 닫아야 하는지”,
“왜 try-with-resources가 필수인지”가 갑자기 전부 연결된다.

---

# 🧠 파일 핸들이란?

간단히 말하면:

> **운영체제가 관리하는 “열린 파일의 출입증”**

프로그램이 파일을 열면,
운영체제는 그 프로그램에게 작은 번호표 하나를 준다.

그 번호표가 바로 **파일 핸들**이다.

---

## 🧱 실제 구조

```
Java 프로그램 ──(open file)──▶ 운영체제
                    ▲
                파일 핸들
```

이 핸들을 통해서만:

* 파일 읽기
* 파일 쓰기
* 위치 이동
* 닫기

같은 작업을 할 수 있다.

---

## 🧩 왜 중요한가?

파일 핸들은 **한정 자원**이다.

* OS는 프로세스마다 열 수 있는 파일 수 제한
* 닫지 않으면 누수
* 누수되면 새 파일 못 염

그래서 이런 에러가 나온다:

> **Too many open files**

---

## 🧪 `Files.lines()`와 파일 핸들

```java
Stream<String> s = Files.lines(path);
```

이 순간:

* 파일 핸들 1개 획득
* OS 파일 테이블에 등록
* 아직 내용은 안 읽음

이 스트림을 닫지 않으면:

* 핸들 반환 안 됨
* 파일 계속 열려 있음
* 리소스 누수

그래서 반드시: **try-with-resources**

```java
try (Stream<String> s = Files.lines(path)) {
    ...
}
```

---

## 🧠 비유

파일 핸들 = 도서관 열쇠
파일 = 도서관 자료실

열쇠 안 반납하면
다음 사람이 못 들어감.

---

## 🏁 한 문장 요약

> 파일 핸들은 **운영체제가 관리하는 열린 파일에 대한 사용권**이며,
> 닫지 않으면 시스템이 서서히 죽는다.

이게 바로 **리소스 관리의 본질**이다.
